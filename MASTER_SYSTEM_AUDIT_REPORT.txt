2. RESOLUTION OF CAMPAIGN BROADCAST STALL (200-RECIPIENT FIX)
================================================================================

Issue Diagnosis:
In previous broadcast campaigns, when broadcasting to 300+ recipients, the worker stopped after ~200 contacts, leaving the remainder in 'PENDING' or 'QUEUED' status.

Root Cause:
In Vercel and Next.js serverless environments, when a worker route handler returns an HTTP response, the underlying Node.js execution runtime is immediately suspended. Any asynchronous unawaited fetch() calls or self-calling recursive webhooks were terminated mid-execution once the 15-second default lambda timeout was reached.

Production Solution Implemented in `src/app/api/whatsapp/campaigns/worker/route.ts`:
1. Configured maximum execution window: `export const maxDuration = 60;`
2. Implemented a continuous execution multi-batch while-loop: `while (Date.now() - startTime < 45000)`
3. Recipient Claiming: Uses atomic PostgreSQL function `claim_campaign_recipients(50)` with `FOR UPDATE SKIP LOCKED` to lock and claim 50 rows per iteration without race conditions.
4. Batch Dispatch: Dispatches Meta Cloud API requests in chunks of 10 with `Promise.allSettled()`.
5. Error Diagnostics: Captures exact Meta error codes (131049, 131056, 131026) per recipient and updates the database row.
6. Auto-Completion: When no pending rows remain, automatically transitions the campaign status to `COMPLETED`.
7. Production Verification: Drained and completed all 313 recipients in the database without stalling.

3. META ECOSYSTEM HEALTH & OPT-IN/OPT-OUT CONSENT ENFORCEMENT
================================================================================

Meta Marketing Frequency Capping & Error 131049 / 131056:
- Meta enforces algorithmic frequency capping across businesses to prevent spam. If a WhatsApp user has received marketing messages from multiple businesses in a 24-48 hour window, Meta will reject delivery with code 131049 ("To maintain healthy ecosystem engagement").
- Meta does NOT bill for messages that fail under error 131049 or 131056.

Opt-In / Opt-Out Architecture:
1. Database Level: Every contact record maintains an `opted_in` BOOLEAN flag (default `true`).
2. Webhook Listener (`src/app/api/whatsapp/webhook/route.ts`): Automatically listens for inbound customer messages containing `STOP`, `UNSUBSCRIBE`, `OPT OUT`, or `CANCEL`. Upon detection, it automatically flips `opted_in = false` and records the opt-out timestamp.
3. Server-Side Filtering (`src/app/api/contacts/route.ts`): Supports `?opted_in=true|false` and returns parallel `{ total, opted_in_count, opted_out_count }` in a single query.
4. Broadcast Guard: Campaign audience builder automatically suppresses all `opted_in = false` contacts, protecting the WhatsApp Business Quality Rating (Green tier).
5. CRM Dashboard: Features 3 interactive luxury KPI cards: Total Audience (879), Opted In Active (872), and Opted Out Protected (7).

6. SALON RFM CUSTOMER LIFECYCLE SEGMENTATION ENGINE
================================================================================

RFM Segmentation Engine (`src/lib/rfm/segmentation.ts` & `src/app/api/rfm/route.ts`):
Automates customer segmentation based on Recency, Frequency, and Monetary parameters:

Segmentation Rules:
1. VIP CLIENTS: Lifetime spend >= Rs. 5,000 OR Total Visits >= 5 OR Explicitly Tagged as VIP.
2. ACTIVE CLIENTS: Visited the salon within the last 44 days.
3. SLIPPING AWAY: Last visit was between 45 and 89 days ago (prime candidates for gentle win-back vouchers).
4. LOST CLIENTS: Last visit was 90+ days ago (requires aggressive reactivation offers).
5. NEW CLIENTS: Added recently with 0 or 1 visit.
6. BIRTHDAY CLUB: Customer birthday occurring within the next 7 days.

Automated Sync Engine (`syncRFMTagsAcrossOrganization`):
Iterates through all organization contacts, computes RFM status, and automatically syncs tag identifiers (`VIP`, `Active Client`, `Slipping Away`, `Lost Client`, `New Client`) directly into the contact's attributes.

7. `conversation_action`: Auto-assign staff or request human agent handover.
8. `end`: Terminate conversation flow.

10. AI TRAINING STUDIO & INTENT CONFIDENCE CLASSIFIER
================================================================================

AI Training Engine (`src/lib/ai/training.ts` & `src/app/api/ai/training/route.ts`):
- Pre-configured Intent Categories: PRICING, BOOKING, SERVICE_INFO, HUMAN_SUPPORT, LOCATION.
- Token-Overlap Classifier: Tokenizes customer input and matches intent phrases regardless of word order.
- Three-Tier Confidence Routing:
  1. Score >= 0.80 -> `AUTO_REPLY`: Dispatches instant automated response.
  2. Score 0.55 - 0.79 -> `CLARIFY`: Prompts customer with quick clarification options.
  3. Score < 0.55 -> `HUMAN_HANDOVER`: Routes chat directly to the reception desk manager in Live Inbox.
